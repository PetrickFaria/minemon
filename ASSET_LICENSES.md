## Charmander Cobblemon 1.8.2 pilot

The Charmander pilot additionally uses the user-provided Cobblemon Fabric 1.8.2 JAR (`Cobblemon-fabric-1.8.2+1.21.1.jar`): its geometry is retained under `src/main/resources/assets/minemon/geo/charmander_cobblemon_1_8_2/`, the base texture under `src/main/resources/assets/minemon/textures/pokemon/charmander_cobblemon_1_8_2/`, and animation JSON under `src/main/resources/assets/minemon/animations/charmander_cobblemon_1_8_2/`. The source model license is included at `assets/minemon/licenses/pokemon/charmander/cobblemon-1.8.2-model-license.txt`. The per-model notice matches the CC BY-NC 3.0 notice retained for the original Charmander assets (SHA-256 `fb8e971d1895863ec9fc5f3cfc526c64af980bd6c93d0a1615c7969df46a6660`). Credit remains **Cobblemon Assets contributors**; the source project license is linked above.

The runtime copy adapts Bedrock `q.` aliases to GeckoLib 3's `query.` names and flattens Bedrock `pre`/`post` plus `lerp_mode` keyframe objects to their source `post` vector (or `pre` when no `post` exists). GeckoLib 3.1.40 then interpolates between the original time/value anchors; the source Catmull-Rom tangents do not have a direct GeckoLib 3 equivalent. Unsupported Bedrock `locators` metadata is removed from the runtime geometry copy; the original geometry JSON retains it. These compatibility steps are scoped to the Charmander copy. It keeps the Cobblemon ground idle and ground walk channels and adds a GeckoLib-compatible finite flame mesh where the supplied tail flame uses zero-width planes. The flame is attached to the source `fire` bone and its visual center keeps the approved local offset from that bone's pivot. The source walk arm rotations already contain the inward rest pose, so the legacy arm-offset patch is skipped for this pilot model. The Minemon-only accelerated walk fallback is not added for Charmander: the source defines no terrestrial `ground_run` clip, so the pilot selects its ground walk at higher entity speeds. These changes are clearly limited to the Charmander pilot model; the original Charmander source files and all other species assets remain intact.

The geometry, texture, and animation are adapted works and remain subject to the source CC BY-NC 3.0 terms. The Minemon JAR containing them is intended for non-commercial testing and must include this attribution plus the per-model license notice.

## Cobblemon Fabric 1.8.2 batch 1 (#001-#010)

The active runtime model, texture, and animation copies for Bulbasaur, Ivysaur, Venusaur, Charmander, Charmeleon, Charizard, Squirtle, Wartortle, Blastoise, and Caterpie now come from the user-provided `Cobblemon-fabric-1.8.2+1.21.1.jar`. The extracted per-model license notice is retained under each species directory at `assets/minemon/licenses/pokemon/<species>/cobblemon-1.8.2-model-license.txt`; the corresponding notices and this attribution are packaged in the JAR. Credit remains **Cobblemon Assets contributors** under the source notice. Minemon does not include Cobblemon Fabric code.

The selected gendered rigs for Bulbasaur, Ivysaur, and Venusaur are the source female variants because the Minemon entity model currently has no gender-specific renderer. All ten source geometry and animation JSONs are preserved as extracted. Runtime adaptations are marked in the batch report and include GeckoLib 3 Molang aliases/keyframes, unsupported locator metadata removal, model-specific bone-channel filtering, and conversion of the three fire-starter flame planes to finite, UV-backed meshes attached to their source flame bones. Charmander alone adds a separate continuously looping tail-flame bone animation. These adaptations do not overwrite the original Minemon asset paths.

Cobblemon `ground_run` is selected only for Venusaur, Charizard, and Blastoise, for which the source pose configuration references that state. Squirtle and Wartortle contain `ground_run` clips in their animation JSONs but have no Gen 1 poser reference in this source JAR, so Minemon does not infer a run selector for them. Their movement remains the source `ground_walk` at higher speeds. This distinction avoids treating an unreferenced clip as an established state.
